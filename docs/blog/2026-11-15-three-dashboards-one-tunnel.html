Three dashboards. One tunnel.

cheap-otto has three web dashboards: Mission Control on :7420, the pixel-agents office on :7421 and the Reviewer with Code Tender on :7430. Until this week they were started three different ways, and their SSH tunnels fought over the same ports. Opening one could break another, and Mission Control did not survive a reboot. Now all three are launchd services on the old MacBook, and one command brings them to your Windows browser through one ssh process.

What you run now

One command installs or updates the services on the Mac, opens the tunnel and opens Mission Control. The rest tell you what is up, or take it back down.

windows → otto-maccheap-otto
# Mission Control + Pixel Office services (the office needs pixel-agents), one tunnel, browser
$ cheap-otto ui --execute
$ cheap-otto ui --execute --open reviewer
# loaded? listening on the Mac? tunnelled here? and if not, why
$ cheap-otto dashboards status --execute
# the Reviewer's own service comes with the deploy, and its ui shares the same tunnel
$ cargo run -p code-reviewer -- m1 sync
$ cargo run -p code-reviewer -- ui
# take it back down
$ cheap-otto dashboards tunnel --stop --execute
$ cheap-otto dashboards uninstall --execute

Like every cheap-otto command that touches the Mac, ui is a dry run until you add --execute. This is what it prints without it, with the default peer:

What changed for you

  • Crashes heal themselves. Each service is a LaunchAgent with KeepAlive, logging to ~/.cheap-otto/logs/dashboards/<id>.log.
  • Re-running is safe. The install script prints action=unchanged for a service that is already right, and frees a port another process holds before it starts one.
  • One tunnel, recorded. tunnel.json holds its pid and ports. A second ui reuses it, and the tool refuses to kill a listener it did not start.
  • The pages link to each other. Mission Control asks GET /api/dashboards which ones are up and links to them. The Reviewer links back to Mission Control.
  • ssh otto-mac is quiet. It no longer forwards dev ports, so it can't collide with the tunnel. Forward 3000, 5173 and 8080 when you need them with cheap-otto pair … --tunnel.
  • No more orphans. The Reviewer's "start Pixel Office" button kicks the LaunchAgent instead of spawning a process outside launchd.

How it was built

Every PR came from its own Claude Code session, branched from main and started as soon as the PRs it depended on had merged, so independent rows ran in parallel. Each one opened its PR and stopped. Cubic reviewed every PR, and Code Tender (the fixer that runs on the Mac next to the reviewer) answered the comments with commits of its own. Once the checks were green and every thread was resolved, the PR auto-merged, one at a time, so only one branch re-ran CI at once.

The honest part: Code Tender is not always right. Once, on #44, its fix contradicted the spec and was reverted. Every fix it made was checked against the spec before merge. And when a Claude session tried to fix the same comment, the two sometimes pushed at once, and one fix was thrown away. Now the task sessions leave review comments to Code Tender.

What's left

Two checks only the owner can run, because they need the real Mac: deploy with m1 sync and verify all ten steps (#29), then reboot the Mac and watch the services come back (#30). The spec, with every requirement and decision, is in specs/m1-dashboards.
