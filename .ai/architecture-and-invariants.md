# `cheap-otto` Unified Workspace Architecture & Invariants

## 1. Two-Crate Cargo Workspace (`Cargo.toml`)
1. **`cheap-otto` (root crate, `src/`):** Cross-OS Dev Bridge & Parallel Agent Worktree Farm pairing a primary workstation (Windows/Linux/macOS) with a headless Apple Silicon MacBook (`otto-mac`) over SSH.
   - **Functional Core / Imperative Shell:** `src/bridge.rs`, `src/worktree.rs`, `src/dashboards.rs`, `src/request_guard.rs`, `src/macos.rs`, `src/hardware.rs`, `src/arbiter.rs`, `src/schedule.rs`, and `src/doctor.rs` generate pure deterministic plans (`CommandSpec` arrays and JSON models) without mutating host state; side effects live strictly in `src/main.rs` and `src/server.rs` behind `--apply` / `--execute` flags.
   - **100% Reversible Clamshell & Battery Protection:** Any `pmset` power/lid modification must snapshot prior macOS values into `.cheap-otto/state-backup.json` before applying changes, cap 24/7 AC battery charge inside `50..=100%` (default `78%`), preserve battery-power fallback sleep (`5 min`), and restore cleanly via `cheap-otto restore`.
   - **Passive Thermal & Unified Memory Guardrails:** Fanless Apple Silicon MacBook Airs throttle under sustained load. The memory arbiter (`src/arbiter.rs`) backs off under `Serious`/`Critical` thermal pressure. The `m1-provision.sh` `launchd` poller wrappers skip a run only when they successfully read a battery percentage below `20%` while on battery, or `kern.thermalstate >= 2`. If `pmset` or `sysctl` is unavailable or returns malformed output, the guard fails open and the job runs. Direct Rust `poll` / `tend-poll` CLI invocations do not yet check thermals themselves.
2. **`code-reviewer` (`crates/code-reviewer`):** Autonomous Multi-Lens Internal CI Reviewer & **Code Tender** review-response engine running on `otto-mac`.
   - **Pure-Rust Zero-AI Polling:** `poll` and `tend-poll` run every 120s via `launchd` using compiled GitHub GraphQL queries and local JSON ledgers (`~/.code-reviewer/state.json`), consuming **0 AI tokens** on idle ticks, draft PRs, clean-pass summaries, or circuit-broken SHAs.
   - **Open-Source Cubic AI + Code Tender Split:** On public repositories reviewed by **Cubic AI** (such as `cokitron/cheap-otto`), internal `code-reviewer` reviews are disabled (`enabled = false`) while Code Tender (`tender_enabled = true`) handles actionable review threads **strictly** for PRs authored by `tender_allowed_authors` (never external contributors or forks).

## 2. State Persistence & Concurrency Invariants
- **Atomic Exclusive Ledger Writes:** Shared state files (`~/.code-reviewer/state.json`) use PID-checked lockfiles + temp-file write + atomic rename. Other `.cheap-otto/*.json` writers do not yet follow this pattern and should be migrated.
- **Overlap Guards & Circuit Breakers:** `poll.lock`, `tender-poll.lock`, and per-PR `workers/*.json` prevent duplicate concurrent sessions on the same `(repo, pr_number)`. Auto-dispatch enforces a 2-attempt circuit breaker per `(head_sha, cursor)` to prevent runaway token loops.
- **Cross-Platform Compilation:** Every workspace crate and test target must compile cleanly and pass `cargo test --workspace --all-targets` across Linux, macOS, and Windows with `#![forbid(unsafe_code)]` and `-D warnings`.
